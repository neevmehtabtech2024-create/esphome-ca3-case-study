# 2. Issue Investigation — ESPHome #16254

**Issue:** https://github.com/esphome/esphome/issues/16254  
**Title:** “Regression in 2026.4.0: substitutions: substitutions in substitutions no longer work”  
**Opened:** 5 May 2026  
**Status:** Closed and linked to PR #16273.

## 2.1 Problem reported
The reporter states that a YAML configuration worked in ESPHome 2026.3.3 and earlier (tested as far back as 2026.2.1), but failed in 2026.4.0 and later. The reporter tested 2026.4.0, 2026.4.1, 2026.4.2, and 2026.4.3. The same error was observed in Docker and the Home Assistant add-on. The issue listed ESP8266 and ESP32, while noting other platforms might also be affected.

## 2.2 Minimal configuration from the issue
```yaml
substitutions:
  device:
    manufacturer: "espressif"
    model: "esp32"
    mac_suffix: "ffffff"
    name: ${device.manufacturer}-${device.model}-${device.mac_suffix}

esphome:
  name: ${device.name}

esp8266:
  board: esp01_1m
```

The example uses an ESP8266 board declaration while the `model` string says `esp32`; for this investigation, the reported failure is in substitution/config parsing, not physical hardware compatibility. Do not interpret this snippet as a recommended hardware configuration.

## 2.3 Expected behaviour
The nested expression for `device.name` should resolve to:
`espressif-esp32-ffffff`

Then `${device.name}` should resolve to that string in `esphome.name`.

## 2.4 Actual behaviour reported
The issue log says the dictionary-like `device` value could not be resolved while resolving its own `name` member. The warning included:
`Could not resolve substitution variable 'device': 'device' is undefined`
The configuration then failed validation because the literal `$` remained in the name.

This log is quoted from the public issue; it is not a log generated by our group.

## 2.5 Root cause described by the PR
The PR explains that a substitutions refactor in 2026.4.0 changed resolution from an in-place tree walk to a pre-resolution pass over top-level substitutions. During resolution of a dictionary-valued substitution, the parent key was removed from the unresolved-variable collection before recursion into its members. A sibling reference such as `${device.manufacturer}` inside `device.name` could therefore no longer find `device`.

This root-cause explanation comes from the PR description, not from an independent source-code debugging session by our group.

## 2.6 Impact
Configurations that rely on sibling references within dictionary-valued substitutions could stop parsing after upgrading to the affected versions. This creates a backwards-compatibility problem for users even though the YAML may have worked in earlier releases.

## 2.7 Issue quality observations
Strengths:
- Specifies the first affected version and earlier working version.
- Includes a minimal YAML example.
- Includes the error log.
- Gives installation environments and platforms tested.
- Provides a command for comparing Docker versions.

Limitations:
- The reporter could not confirm whether every supported platform was affected.
- The configuration example mixes an `esp32` model string with an `esp8266` board declaration; this does not invalidate the reported substitution failure but can confuse readers about hardware.
